## Phase 0 — Prerequisites

### P0.0 — Fix commission rate trigger ⚠️ URGENT — do before any new partner sales

**Problem:** The live DB trigger `record_partner_commission_on_order()` calculates commission rate based on order price:

```sql
-- CURRENT (WRONG) — price-based tiering
v_rate := CASE WHEN COALESCE(NEW.price, 0) >= 50 THEN 0.20 ELSE 0.15 END;
```

**Correct logic:** Volume-based tiering — 15% for sales 1–49, 20% from sale 50 onwards.

**Required change 1 — Fix the trigger rate logic:**

```sql
-- CORRECT — volume-based tiering
SELECT COUNT(*) INTO v_completed_sales
FROM partner_commissions
WHERE partner_code = v_partner_code;

v_rate := CASE WHEN v_completed_sales >= 49 THEN 0.20 ELSE 0.15 END;
```

`v_completed_sales` counts existing rows in `partner_commissions` for this partner code before the new one is inserted. If 49 or more rows already exist (i.e. this is sale 50 or above), apply 20%. Otherwise 15%.

**Required change 2 — Add `rate` column to `partner_commissions`:**

```sql
ALTER TABLE partner_commissions
ADD COLUMN rate numeric NOT NULL DEFAULT 0.15;
```

Update the trigger to store the computed rate into this column on every insert.

Update the existing 1 row: set `rate = 0.15` (confirmed correct — it was the first sale).

**Verification after deployment:**
- Show the updated trigger function body from the DB
- Confirm the existing row now has `rate = 0.15`
- Confirm RLS policies on `partner_commissions` are unchanged (still admin-only)

## Phase 1 — Partner data edge function

### P1.1 — New edge function: `get-partner-dashboard`

This is the single server-side function that serves all data to the partner frontend. Partners never query `partner_commissions` or `consignment_orders` directly.

**Location:** `supabase/functions/get-partner-dashboard/index.ts`

**Logic (in order):**

1. Read the caller's authenticated session from the request JWT. If no valid session: return 401.
2. Look up `profiles.role` for `auth.uid()`. If role is not `partner`: return 403.
3. Query `referral_codes` where `user_id = auth.uid()` AND `type = 'partner'` AND `is_active = true`. Extract `code` and `id`. If not found: return 404 with message "No active partner code found."
4. Using the **service role key** (not the anon key): query `partner_commissions` where `partner_code = <their_code>`. Return all rows ordered by `commission_date DESC`.
5. Using the **service role key**: query `consignment_orders` where `partner_id = auth.uid()`. Return all rows ordered by `created_at DESC`.
6. Compute summary totals server-side:
   - `commission_total_earned`: sum of `amount` where status in ('owed', 'paid')
   - `commission_total_paid`: sum of `amount` where status = 'paid'
   - `commission_total_pending`: sum of `amount` where status = 'owed'
   - `consignment_total_pending`: sum of `total_value` where status = 'pending'
   - `consignment_total_paid`: sum of `total_value` where status = 'paid'
7. Return a single JSON payload:

```json
{
  "partner": {
    "code": "PRAIATUR",
    "label": "Praiatur",
    "uses_count": 1
  },
  "summary": {
    "commission_total_earned": 0.00,
    "commission_total_paid": 0.00,
    "commission_total_pending": 0.00,
    "consignment_total_pending": 0.00,
    "consignment_total_paid": 0.00
  },
  "commissions": [...],
  "consignment_orders": [...]
}
```

**Logging rules:** Do not log customer email addresses, full order IDs, or any financial amounts. Log only: function invoked, partner_code resolved, row counts returned, errors.

**Add to `supabase/config.toml`** if not already present. Deploy alongside existing functions without modifying any other function.

## Phase 3 — Consignment infrastructure

### P3.1 — New table: `consignment_orders`

```sql
CREATE TABLE consignment_orders (
  id             uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  partner_id     uuid NOT NULL REFERENCES auth.users(id) ON DELETE RESTRICT,
  partner_code   text NOT NULL,
  batch_id       text,
  plan_name      text NOT NULL,
  quantity       integer NOT NULL CHECK (quantity > 0),
  unit_price     numeric NOT NULL CHECK (unit_price >= 0),
  total_value    numeric GENERATED ALWAYS AS (quantity * unit_price) STORED,
  status         text NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'paid')),
  paid_at        timestamptz,
  notes          text,
  created_at     timestamptz NOT NULL DEFAULT now(),
  updated_at     timestamptz NOT NULL DEFAULT now()
);

ALTER TABLE consignment_orders ENABLE ROW LEVEL SECURITY;
```

**RLS policies — two only:**

```sql
-- Admin: full access
CREATE POLICY "Admins can manage consignment orders"
ON consignment_orders
FOR ALL
USING (get_current_user_role() = 'admin')
WITH CHECK (get_current_user_role() = 'admin');

-- Partner: read own rows only
CREATE POLICY "Partners can view their own consignment orders"
ON consignment_orders
FOR SELECT
USING (auth.uid() = partner_id);
```
